# 01 — Requirements

專案：BookSwap｜二手教科書「雙向換書」媒合
狀態：Design Only

---

## 1. Problem

學期交替時，學生手上有用不到的教科書，同時也需要買下學期的教科書。現行管道（社團貼文、群組訊息）的每一則訊息都是**單向**的：要嘛只寫「讓售」，要嘛只寫「徵求」。

想換書的人必須：

1. 翻完所有「讓售」貼文，找出有沒有自己要的書
2. 再翻完所有「徵求」貼文，找出有沒有人要自己的書
3. 在腦中把兩邊的人名交叉比對，才知道有沒有人可以跟自己直接互換

第 3 步實務上沒有人會做，所以**可互換的組合幾乎都錯過了**。

## 2. User

| 項目 | 內容 |
|---|---|
| 主要使用者 | 同校大學生（以下稱「成員 / Member」） |
| 前提 | 成員已有 `memberId`（校內既有識別，本系統不處理註冊與登入） |
| 使用時機 | 學期末（想出清）、學期初（想取得） |
| 使用者能力 | 知道自己書的 ISBN，或可從書背掃到 |

## 3. Scenario（亮點如何幫使用者完成任務）

小美修完資料結構，課本用不到了；下學期要修作業系統，需要那本課本。

**現行做法**：小美到二手書社團發一則「讓售資料結構」，再發一則「徵求作業系統」。兩則貼文淹沒在當天 50 則訊息裡。她每天回來翻一次，看有沒有人回。一週後放棄，直接買新書。

**使用 BookSwap**：

1. 小美建立 Listing：ISBN `9789861579993`《資料結構》，書況 `GOOD`
2. 小美建立 Wish：ISBN `9780133591620`《作業系統》
3. 小明（她不認識）前一天剛好做了相反的兩件事
4. 小美呼叫 `GET /members/M001/matches`
5. 系統即時交叉比對，回傳一筆配對：
   - 對方：小明（M002）
   - 小美給出：《資料結構》
   - 小美拿到：《作業系統》
6. 兩人線下換書，小美把自己的 Listing 下架

**亮點的可觀察改善**：原本需要人工比對兩份清單（且實際上沒人會做），現在是一次 API 呼叫得到明確的「誰、換什麼、換到什麼」。從「翻 50 則貼文後仍不確定」變成「一個清單，每一筆都已經確認雙方都想要」。

## 4. Scope

### In Scope

- 刊登可讓出的教科書（以 ISBN 識別）
- 登記想要的教科書（以 ISBN 識別）
- 查詢「雙向可互換」的配對清單
- 下架已換出或不想換的刊登

### Out of Scope

- 註冊、登入、認證、授權
- 金流、定價、議價
- 站內訊息、通知、Email
- 評價、檢舉、信用機制
- 三方以上循環換書（A→B→C→A）
- 書況照片、全文/書名模糊搜尋
- 配對結果的持久化與「交易狀態機」（見 BR-05）

---

## 5. Functional Requirements

| ID | 需求 | 說明 |
|---|---|---|
| **FR-01** | 刊登可讓出的教科書 | 成員可建立一筆 Listing，包含 ISBN、書名、書況。建立後狀態為 `AVAILABLE`。 |
| **FR-02** | 登記想要的教科書 | 成員可建立一筆 Wish，包含 ISBN、書名。 |
| **FR-03** | 查詢雙向互換配對清單 | 成員可取得所有與自己「雙向可成交」的對象清單，每筆載明對方、自己要給出哪本、自己會拿到哪本。**（系統亮點）** |
| **FR-04** | 下架刊登 | 成員可將自己的 Listing 狀態改為 `REMOVED`，使其不再出現在任何人的配對結果中。 |

---

## 6. Business Rules

| ID | 規則 |
|---|---|
| **BR-01** | ISBN 為書本的唯一比對鍵，格式為 13 碼數字（ISBN-13）。不符格式一律拒絕，不做自動轉換或補零。 |
| **BR-02** | 同一成員對同一 ISBN 最多只能有一筆 `AVAILABLE` 的 Listing；重複建立視為衝突。Wish 同理，同一成員對同一 ISBN 只能有一筆。 |
| **BR-03** | Listing 只有兩種狀態：`AVAILABLE`、`REMOVED`。只有 `AVAILABLE` 的 Listing 參與配對。狀態變更為單向，`REMOVED` 不可復原（要重新上架請建立新的 Listing）。 |
| **BR-04** | **雙向配對（Mutual Match）成立條件**：對成員 A 與成員 B（A ≠ B），存在書 X、Y 使得<br>① A 有 `AVAILABLE` Listing(X) 且 B 有 Wish(X)<br>② B 有 `AVAILABLE` Listing(Y) 且 A 有 Wish(Y)<br>四個條件必須同時成立。單向成立（只有 ① 或只有 ②）**不**算配對，不回傳。 |
| **BR-05** | 配對結果不持久化。每次呼叫 FR-03 都依當下的 Listing / Wish 即時計算。**取捨理由**：若把 Match 存成實體，就必須處理「提出 → 接受 → 拒絕 → 過期」的交易狀態機與雙方同步，規模遠超本題；即時計算可完整支撐亮點，且永遠不會出現「配對已存在但書早就下架」的過期資料。 |
| **BR-06** | 書況 `condition` 僅允許 `NEW`、`GOOD`、`FAIR`、`POOR` 四值。 |
| **BR-07** | 成員自己的 Listing 不與自己的 Wish 配對（A ≠ B 已排除，此處明文載明以免實作誤解）。 |
| **BR-08** | 同一對成員之間若有多組可互換的書，回傳多筆 Match（每筆是一組 X/Y 組合），不自動擇一。 |
| **BR-09** | 所有操作皆以 Request 中的 `memberId` 為行為人，系統不驗證其身分（Out of Scope）；但 `memberId` 必須存在於 Member 資料中，否則拒絕。 |

## 7. Acceptance Criteria

### FR-01 刊登可讓出的教科書

| # | Given | When | Then |
|---|---|---|---|
| AC-01-1 | 成員 M001 存在，且沒有 ISBN `9789861579993` 的 AVAILABLE Listing | 以合法 ISBN、書名、`condition=GOOD` 建立 Listing | 回傳 `201`，內含新 `listingId` 與 `status=AVAILABLE` |
| AC-01-2 | 同上 | ISBN 傳入 `978986157999`（12 碼） | 回傳 `400`，不建立任何資料（BR-01） |
| AC-01-3 | M001 已有 ISBN `9789861579993` 的 AVAILABLE Listing | 再次以同一 ISBN 建立 | 回傳 `409`（BR-02） |
| AC-01-4 | M001 該 ISBN 的 Listing 狀態為 REMOVED | 以同一 ISBN 建立 | 回傳 `201`（BR-03：REMOVED 不佔用名額） |
| AC-01-5 | `memberId` = `M999` 不存在 | 建立 Listing | 回傳 `404`（BR-09） |
| AC-01-6 | — | `condition` 傳入 `BROKEN` | 回傳 `400`（BR-06） |

### FR-02 登記想要的教科書

| # | Given | When | Then |
|---|---|---|---|
| AC-02-1 | 成員 M001 存在，無該 ISBN 的 Wish | 以合法 ISBN 建立 Wish | 回傳 `201`，內含 `wishId` |
| AC-02-2 | M001 已有該 ISBN 的 Wish | 重複建立 | 回傳 `409`（BR-02） |
| AC-02-3 | `memberId` 不存在 | 建立 Wish | 回傳 `404` |

### FR-03 查詢雙向互換配對清單（亮點）

| # | Given | When | Then |
|---|---|---|---|
| AC-03-1 | M001 有 Listing(X)、Wish(Y)；M002 有 Listing(Y)、Wish(X) | `GET /members/M001/matches` | 回傳 `200`，`matches` 含 1 筆，`partnerId=M002`，`give` 指向 X、`receive` 指向 Y |
| AC-03-2 | M001 有 Listing(X)、Wish(Y)；M002 只有 Wish(X)，沒有 Listing(Y) | 同上 | 回傳 `200`，`matches` 為空陣列（BR-04：單向不算） |
| AC-03-3 | 條件同 AC-03-1，但 M002 的 Listing(Y) 已 `REMOVED` | 同上 | 回傳 `200`，`matches` 為空陣列（BR-03） |
| AC-03-4 | M001 自己同時有 Listing(X) 與 Wish(X) | 同上 | 回傳 `200`，不含自己配自己的結果（BR-07） |
| AC-03-5 | M001 與 M002 之間有兩組可互換組合 | 同上 | 回傳 `200`，`matches` 含 2 筆（BR-08） |
| AC-03-6 | `memberId` 不存在 | 同上 | 回傳 `404` |

### FR-04 下架刊登

| # | Given | When | Then |
|---|---|---|---|
| AC-04-1 | Listing L001 存在且為 AVAILABLE | `DELETE /listings/L001` | 回傳 `204`，該 Listing 狀態變為 `REMOVED` |
| AC-04-2 | 承 AC-04-1，L001 原本促成一筆 Match | 對方再次查詢配對 | 該筆 Match 不再出現（BR-03 + BR-05） |
| AC-04-3 | L001 不存在 | `DELETE /listings/L001` | 回傳 `404` |
| AC-04-4 | L001 已是 REMOVED | 再次刪除 | 回傳 `404`（已下架的刊登視同不存在，BR-03） |
